# Duel-Channel 公网入口安全加固设计

## 目标

面向通过 HTTPS 反向代理公开访问的自托管实例，确保网关按可信客户端地址执行现有限额，并避免公开状态页披露运行详情。保留现有游戏协议、匹配与房间行为。

## 已确认的边界

- `server/gateway.mjs` 在启用 `TRUST_PROXY=1` 时直接采用 `X-Forwarded-For` 第一项，未校验地址格式，也未确认 TCP 对端是否为代理。
- WebSocket 会话、房间创建、比赛数量和邀请码失败次数使用 `clientIp()` 得到的地址；错误报告限额则直接使用 TCP 对端地址。
- `/status` 对所有网络开放，并返回队列昵称、实例状态、错误摘要等信息；只有房间邀请码按 loopback 远端地址隐藏。`/healthz` 提供精简存活信息。
- `docs/DEPLOY.md` 已要求公网部署使用反向代理，并警告直接暴露 `TRUST_PROXY=1` 会使客户端能够伪造转发地址。
- Stronghold-Protocol 的 `server/net.js` 使用标准 IP 校验、规范化，并只从 loopback/私网连接接受转发地址；其 X-Forwarded-For 解析采用最后一项。本设计只复用适用于本仓库的边界，不复制其 WebSocket 协议和连接管理。

## 方案

### 客户端地址

新增一个小型、可单独验证的地址解析函数，供 WebSocket 接入限额与 `/report` 错误报告限额共用。

1. 未设置 `TRUST_PROXY=1` 时，完全忽略转发头，使用 TCP 对端地址。
2. 设置 `TRUST_PROXY=1` 时，仅当 TCP 对端为 loopback 或私有地址时读取 `X-Forwarded-For`。
3. 转发链只解析最右侧地址；该值必须通过 Node `net.isIP()` 校验。IPv4-mapped IPv6 地址规范化为 IPv4。
4. 转发地址缺失或无效时回退到 TCP 对端地址。loopback 仍按现有规则不计入公网网络限额。
5. 位于公网地址上的代理不会自动受到信任。部署文档说明此版本要求网关看到的代理对端为 loopback 或私网地址；公网代理地址白名单属于单独后续设计。

反向代理配置必须先清除客户端提交的 `X-Forwarded-For`，再写入代理实际观察到的客户端地址，避免把客户端可控值作为可信链的一部分。

### 状态与健康检查

- `/status` 仅允许解析后的客户端地址为 loopback 时读取；其他地址收到 `404` 和空响应。启用代理信任时，判断使用经校验的转发地址。
- `/healthz` 保持公网可访问，响应字段和状态码不变。
- 反向代理必须阻止公网请求访问 `/status`，只转发 `/healthz`；当代理未提供可验证地址时，网关无法仅凭 loopback 代理连接区分本机与公网请求。

### 文档

更新 `docs/DEPLOY.md` 与 `SECURITY.md`，说明：公网服务必须放在 HTTPS 反向代理之后；网关端口应限制为本机/私网可达；代理需覆盖入站转发头并屏蔽公网 `/status`；`TRUST_PROXY=1` 只在 loopback/私网代理部署下生效；公网监控使用 `/healthz`，详细状态仅在服务器本机查询。

## 错误处理

无效、缺失或格式错误的转发地址不会使请求失败，也不会被当作限额身份；解析器回退到 TCP 对端。未知或公网代理对端同样按 TCP 对端限额。无效 `TRUST_PROXY` 值沿用当前行为，即不信任转发头。

## 验收

- 单元测试覆盖直连忽略转发头、可信私网代理使用最右侧合法地址、无效/缺失值回退、IPv4-mapped IPv6 规范化，以及公网代理对端不受信任。
- 网关测试确认本机可读取 `/status` 完整状态，带有外部客户端转发地址的代理请求无法读取；`/healthz` 仍可读取且保持精简响应。
- 测试确认 WebSocket 与报告限额使用同一地址解析结果。
- 定向测试、相关现有网关测试、lint 与 `git diff --check` 通过；不以静态检查代替上述行为测试。

## 不在本轮范围

- 重新设计客户端 `cid` 或会话身份协议。
- 新增跨节点共享限流、全局未认证连接额度或用户账号系统。
- 新增来源域名白名单、CSP 或游戏玩法校验。
- 自动信任公网 CDN/代理地址段。
